# GasMate

A modern port of the original 2013 Java Play Framework 1.x "egassewa" college project — an online LPG gas agency management system — rebuilt in Go with HTMX and SQLite.

## Tech stack

| Concern | Choice |
|---|---|
| HTTP server | `net/http` (stdlib) |
| Templates | `html/template` (stdlib) |
| Database | `database/sql` + SQLite (`modernc.org/sqlite`, pure Go — no CGo) |
| Password hashing | `golang.org/x/crypto/bcrypt` |
| Sessions | HMAC-SHA256 signed cookies (stdlib `crypto/hmac`) |
| Email | `net/smtp` (stdlib) |
| Frontend interactivity | Self-contained HTMX-compatible JS (no CDN dependency) |
| Styling | Custom CSS (no framework) |

**2 external dependencies.** Compiles to a single self-contained binary.

---

## Prerequisites

- Go 1.22 or newer ([install](https://go.dev/dl/))

That's it. No database server, no Node.js, no Docker required.

---

## Quickstart

```bash
# Clone the repo and enter the project directory
git clone https://github.com/glnarayanan/egassewa.git
cd egassewa/gasmate

# Download dependencies
go mod download

# Run the development server
go run .
```

The server starts on **http://localhost:8080**.

On first boot, the database is created at `gasmate.db` in the current directory and seeded with:
- 5 states, 13 cities (India)
- 6 gas cylinder types (domestic: 2/5/14 kg; commercial: 19/35/47.5 kg)
- 9 accessories (stoves, regulators, hose, etc.)

---

## Building a binary

```bash
go build -o gasmate .
./gasmate
```

The resulting `gasmate` binary embeds all templates, CSS, and JS — nothing else is needed to run it.

## Environment variables

All variables are optional. Defaults are shown.

| Variable | Default | Description |
|---|---|---|
| `PORT` | `8080` | HTTP listen port |
| `DB_PATH` | `gasmate.db` | Path to the SQLite database file |
| `SMTP_HOST` | _(empty)_ | SMTP server hostname. If unset, emails are logged to stdout instead of sent. |
| `SMTP_PORT` | `587` | SMTP server port |
| `SMTP_USER` | _(empty)_ | SMTP username |
| `SMTP_PASS` | _(empty)_ | SMTP password |
| `SMTP_FROM` | `gasmate@example.com` | Sender address for outgoing emails |

Example with all options set:

```bash
PORT=9090 \
DB_PATH=/var/data/gasmate.db \
SMTP_HOST=smtp.gmail.com \
SMTP_USER=you@gmail.com \
SMTP_PASS=your-app-password \
SMTP_FROM=noreply@yourdomain.com \
./gasmate
```

> **Email without SMTP:** If `SMTP_HOST` is not set, the app runs normally — every email that would have been sent is printed to the server log instead. This is the default for local development.

## First-time setup: creating an admin account

The seed data does not create any user accounts. To get started you need an admin account, then use the admin portal to create dealers, after which customers can self-register.

**Option A — using the Go toolchain (recommended for local dev):**

```bash
# Generate a bcrypt hash for your chosen password
go run -v . &          # start the server in background
# ... or use this one-liner to get a hash without starting the server:
go run ./cmd/hashpw    # (see below)
```

Alternatively, use a small helper script. From inside `gasmate/`:

```bash
go run - <<'EOF'
package main

import (
    "fmt"
    "golang.org/x/crypto/bcrypt"
)

func main() {
    hash, _ := bcrypt.GenerateFromPassword([]byte("adminpassword"), bcrypt.DefaultCost)
    fmt.Printf("INSERT INTO accounts(username,email,password_hash,role,unique_number)\nVALUES('admin','admin@example.com','%s','admin','ADMIN001');\n", hash)
}
EOF
```

Copy the generated `INSERT` statement, then run it against the database:

```bash
# If you have sqlite3 installed:
sqlite3 gasmate.db "<paste INSERT here>"

# Or pipe it:
go run - <<'EOF' | sqlite3 gasmate.db
... (same script as above)
EOF
```

**Option B — using any SQLite GUI:**

Open `gasmate.db` with [DB Browser for SQLite](https://sqlitebrowser.org/) or any compatible tool, and run:

```sql
-- Replace the hash with one generated by bcrypt (cost 10)
INSERT INTO accounts (username, email, password_hash, role, unique_number)
VALUES (
    'admin',
    'admin@example.com',
    '$2a$10$<your-bcrypt-hash-here>',
    'admin',
    'ADMIN001'
);
```

> You can generate a bcrypt hash at https://bcrypt-generator.com/ (use cost 10).

Once the admin account exists, log in at **http://localhost:8080/login**.

## Typical setup workflow

After creating an admin account, the recommended order is:

1. **Log in as admin** → `/admin/cylinders`
2. **Add cities** if needed → `/admin/cities` (13 are pre-seeded)
3. **Create at least one dealer** → `/admin/dealers`  
   (This creates a dealer account with a generated `DLR#####` ID.)
4. **Give the dealer their credentials** so they can log in at `/login`
5. **Customers register** at `/signup` — they choose a city and dealer during registration
6. **Customers book** cylinders at `/user/book`, dealers confirm/dispatch at `/dealer/orders`

## User roles

| Role | Entry point after login | Created by |
|---|---|---|
| `admin` | `/admin/cylinders` | Manual DB insert (see above) |
| `dealer` | `/dealer/orders` | Admin via `/admin/dealers` |
| `customer` | `/user/book` | Self-registration at `/signup` |

## Feature overview

### Customer portal (`/user/...`)
- **Book Cylinder** — choose a cylinder type; enforces a 20-day cooldown between bookings of the same type
- **My Orders** — view all cylinder and accessory order history with status
- **Order Accessories** — browse and order stoves, regulators, hoses, etc.
- **Profile** — view gas connection number; update address and phone
- **New Connection** — submit an application for an additional gas connection
- **Change Location** — request a dealer/city transfer
- **End Service** — submit a termination request

### Dealer portal (`/dealer/...`)
- **Cylinder Orders** — view incoming orders; confirm or dispatch with a single click (HTMX, no page reload); each action triggers an email to the customer
- **Accessory Orders** — same flow for accessory orders
- **Customers** — view all customers assigned to this dealer

### Admin portal (`/admin/...`)
- **Cylinders** — add/delete cylinder types and pricing
- **Accessories** — add/delete accessories and pricing
- **Dealers** — create dealer accounts (auto-assigns a `DLR#####` ID)
- **Customers** — read-only view of all registered customers
- **Cities** — add cities to states
- **Requests** — review and approve/reject new connection requests, location changes, and end-service requests

---

## Order status flows

**Cylinder orders:**
```
WAITING → CONFIRMED → DISPATCHED
                    ↘ CANCELLED
```

**Accessory orders:**
```
PENDING → CONFIRMED → DISPATCHED
```

An email notification is sent to the customer at every status transition (if SMTP is configured).

## Design notes

**Template system:** Go's `html/template` has a "last `{{define}}` wins" pitfall when all templates share one `*template.Template`. Each page instead gets its own clone of the layout template (`template.Clone()`) with only its own content defines parsed in — avoiding conflicts while keeping templates embedded at build time.

**Sessions:** No JWT library or session store needed. The session is a base64-encoded JSON payload signed with HMAC-SHA256 using a randomly generated key at startup. The key is ephemeral (regenerated on restart), which invalidates all sessions — acceptable for this use case.

**HTMX:** Since external CDNs are not required, a self-contained ~80-line implementation lives in `static/js/htmx.min.js`. It covers the subset of HTMX attributes used in this project: `hx-get`, `hx-post`, `hx-delete`, `hx-target`, `hx-swap`, `hx-vals`, `hx-include`, `hx-trigger`, `hx-confirm`.

**SQLite concurrency:** `db.SetMaxOpenConns(1)` ensures a single writer to SQLite. WAL journal mode is enabled for better read concurrency.
